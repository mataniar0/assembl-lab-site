# MVP-04 — פרטיות ואבטחה: בקרות פיתוח וגבולות פריסה

**סטטוס:** DEV SAFETY BASELINE, NOT PRODUCTION SECURITY SIGN-OFF.  
**זרימת נתונים בפיתוח:** Synthetic Design Intent -> localhost mock backend -> in-memory job. אין צילום חדר, אין תמונת פלט, אין חיוב, אין משתמשים אמיתיים.  
**בעל החלטות מדיניות:** בעל הפרויקט. אישורי אבטחה ופרטיות מקצועיים נדחו, לא סומנו כ־PASS.

## בקרות ממומשות
1. השרת מיועד לפעול בכתובת \`127.0.0.1\` בלבד, ואינו פותח CORS לדפדפן.
2. הפעולות מחייבות \`Authorization: Bearer ...\` עם סוד פיתוח מהסביבה (אורך 24+), שאינו שמור במאגר.
3. בנוסף נדרש \`X-Dev-Session\`. זהו **מזהה פיתוח לא מאומת, אינו Auth אמיתי**, ואסור להשתמש בו לשליטה בגישה בייצור.
4. שירות ה־mock מקבל רק \`source_kind: synthetic\`. כל בקשה לתמונה אמיתית נדחית ללא תלות בהסכמה.
5. בקשת \`POST\` מוגבלת ל־32KiB JSON, ומותרות רק השדות \`source_kind\`, \`design_intent\`.
6. \`Idempotency-Key\` מגן מפני יצירת עבודה כפולה; שינוי payload עם אותו מפתח מוחזר כ־409.
7. חמש עבודות פעילות לכל Dev Session במופע הזיכרון; אחרי DELETE ניתן לנצל מקום שוב. **לא** מגבלת עלות עמידה בפני תקיפה.
8. GET/DELETE מחזירים 404 כאשר מזהה העבודה אינו שייך לסשן המבקש.
9. אין כתיבת דיסק, storage או תמונות; מידע בזיכרון נמחק עם סגירת השרת. אין לוג של פרומפט, מפתח, תמונה או גוף בקשה.
10. Response headers: \`Cache-Control: no-store\`, \`nosniff\`, \`referrer-policy: no-referrer\`, \`X-Frame-Options: DENY\`.

## Threat model — דברים שאינם פתורים עדיין
| איום | בקרת פיתוח | חסם לפרודקשן |
|---|---|---|
| דליפת צילום בית | העלאות תמונה נדחות | אחסון פרטי, short-lived URLs, מחיקה מתוזמנת |
| גניבת מפתח API | אין ספק AI ואין מפתח בקוד | secret manager, key rotation, log redaction |
| דליפת מידע בין לקוחות | סשנים מדומים מופרדים | Supabase Auth/RLS או זהות מאומתת אחרת, בדיקות cross-tenant |
| ניצול עלויות API | אין קריאות בתשלום; quota זיכרון | durable quota, spending budget, abuse controls |
| כפילות פעולות | Idempotency-Key בזיכרון | unique index ב־DB + טרנזקציות |
| SSRF/העלאות קבצים | אין URL fetch או uploads | MIME sniffing, גודל, פענוח בטוח, חסימת URL חיצוניים |
| הצפת בקשות | loopback בלבד ומגבלה ל־32KiB | rate limit ב־gateway, timeouts ותורים |
| פגיעה בפרטיות logs | אין תיעוד body או סוד | logs מינימליים + retention/Audit מוגבל |
| שימוש בתוצר כייצור | \`MOCK_READY\`, \`engineering_approval=false\` | שער אנושי לפני CAD/ייצור |

## מדיניות מוצעת שעדיין דורשת החלטת בעל הפרויקט
- **הסכמה:** לפני העלאת צילום לבית השרת יש להציג שימוש, ספק AI, זמן שמירה ואופן מחיקה; נדרש opt-in מפורש.
- **Retention:** לבחור משך שמירה (למשל 7 ימים לפיילוט) בהתאם לצורך ולהנחיות משפטיות; כל עוד לא אושר — אין העלאת תמונות.
- **מחיקה:** DELETE חייב להסיר במערכת ייצור גם מקור, תוצר, metadata, קישורי שיתוף ועותקים נלווים לפי מדיניות.
- **הרשאות:** גישה של מפעיל ייצור בנפרד מזיהוי לקוח, הצגת מינימום פרטי בית, Audit.
- **תנאי שימוש/דין:** לוודא מדיניות מתאימה לאזור המשתמשים, ולקבל אישור לפני פתיחת שירות קצה ללקוחות.

**החלטת אבטחה:** אין להפוך את שרת הדוגמה לשרת ציבורי. לפני חיבור PWA ל־Backend, יש לממש אימות אמיתי, אחסון פרטי, rate-limit עמיד, שימור/מחיקה ומנגנון consent. בדיקות QA העצמאיות עדיין נדחות לבקשת המשתמש, אך בדיקות בסיס לחסמים אלה נדרשות לפני תמונה אמיתית.
