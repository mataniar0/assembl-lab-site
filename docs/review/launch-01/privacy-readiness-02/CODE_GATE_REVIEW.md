## משמעות שערי WUL

בקוד WUL, ‏`canSend` דורש `privacyApproved === true`, טקסט הודעה בשתי שפות, `formDestinationApproved === true` ויעד תקין. `contactDetailsApproved` שולט בערוצי email/WhatsApp; הוא **אינו תנאי שלישי ל־Formspree** באותו אופן כמו ב־ASSEMBL. לכן אין לייחס ל־WUL את מטריצת שלושת האישורים של PR #26. בתצורה הקיימת שלושת הדגלים false והשליחה חסומה; זה אומת בעבר ונשאר מתאים ל־SHA הנוכחי. אין שינוי בהתנהגות במסגרת סקירה זו.

## מוכנות לפרסום לעומת מצב שפורסם

**אין ראיה שהתיקון של #21 מוזג או פורסם.** main AS אינו עומד בשערי המועמד, וענף המסמכים #19 אינו כולל את תיקון הטופס. אין לחבר בין מדיניות מהענף האחד לקוד מהאחר ולכנות זאת “גרסה משולבת שנבדקה”. מקור Git אינו צילום של ה־deployment; ה־SHA הציבורי והתנהגות הציבור לא אומתו בגלל חסימות קודמות. לא הופעל probe חוזר ללא שינוי התנאים.

אין קישור HTML שנצפה אל טיוטת מדיניות לא מאושרת; זו תוצאה טובה **במקורות שנבדקו בלבד**. היעדר קישור ציבורי לטיוטה אינו תחליף לקישור למדיניות סופית מאושרת. לאחר קבלת אישור לטקסט, נדרשים שילוב נפרד, בדיקה של SHA משולב ובדיקה ציבורית קריאה בלבד. אין לאשר הפעלת דגלים כתוצר אוטומטי של אישור טקסט או merge עתידי.
